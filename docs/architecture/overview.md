# Architecture overview

`@panmdaa/server` is a from-scratch HTTP and WebSocket server for Node.js. It has **zero runtime dependencies** and is built around two engines that share the same philosophy:

- `src/router/` — a radix-tree based router with a compiled-regex fast path.
- `src/http/` + `src/ws/` — the HTTP request pipeline and the WebSocket stack.

## Module map

```

├── index.ts                 ← root barrel: re-exports error, http, middleware, router, ws

├── router/
│   ├── router.ts            ← Router: use/all/verbs/ws, route registration
│   └── radix-tree/          ← RadixTree matching engine
├── http/
│   ├── handler/             ← compileHandler (middleware chain compiler)
│   ├── context/             ← ContextHttpHandler, ContextBodyHandler, ContextWSHandler
│   │   ├── body/            ← BodyContext (raw/json/text/formData/stream)
│   │   └── response/        ← ResponseContext
│   └── server/              ← Server class + native server creation + upgrade
├── ws/
│   ├── handshake/           ← RFC 6455 handshake (HTTP/1 + HTTP/2)

│   ├── connection/          ← WebSocketConnection state machine

├── middleware/              ← public barrel; cors, securityHeaders
└── scripts/                 ← build tooling (mime generation, run-all)
```

## Design philosophy

The library optimizes for **three things, in order**:

1. **Performance** — the hot path is allocation-light and syscall-aware. Static routes are O(1) map lookups, the WebSocket parser reuses a single frame object, responses are ended by Node itself when nothing was written.
2. **Zero dependencies** — everything (routing, masking, compression wiring, body parsing, multipart) is implemented in-repo. `node:zlib` is used for the actual deflate/inflate; no third-party addons like `bufferutil` or `ws`.
3. **TypeScript ergonomics** — route paths are type-checked (`/user/:id` gives you `params.id: string`), contexts are discriminated by verb, and middleware is compiled into typed handlers.

## The two pipelines

### HTTP (one request)

1. Node emits `request` (`src/http/server/server.ts:37`).
2. `Server.request` finds a route: `this.find(method, url)` (`server.ts:151`).
3. A context is built by verb — body methods get `ContextBodyHandler`, the rest `ContextHttpHandler` (`server.ts:84`).
4. The compiled handler runs (`server.ts:116`). If it returned a promise, the response is ended when it settles; otherwise it is ended synchronously.
5. Unmatched paths get 405/404 with an `Allow` header; `HEAD` falls back to `GET`; `OPTIONS` is auto-answered (`server.ts:162-201`).

### WebSocket (one upgrade)

1. Node emits `upgrade` for HTTP/1 (`server.ts:51`) or an extended CONNECT stream for HTTP/2 (`server.ts:47`).
2. `WebSocketUpgrader` finds a WS route, validates headers, writes the `101` and creates a `WebSocketConnection` (`src/http/server/websocket.ts:39`).
3. `runWebSocketHandler` dispatches into your handler with `ContextWSHandler` (`websocket.ts:104`).
4. Frames flow through the connection's zero-alloc parser and are emitted as `text`/`binary`/`message` events.

## Shared hot-path tricks

Both engines follow the same allocation discipline:

| Trick | Where |
|-------|-------|
| Static routes in a flat map, shared immutable `FindResult` | `internal-radix-tree.ts:240` |
| Dynamic routes compiled to one regex per method | `internal-radix-tree.ts:302` |
| Reused frame object for WebSocket parsing | `connection.ts:60`, `parser.ts:28` |
| Lazy context members (response, headers, body, query, cookies) | `http-handler.ts:44`, `body-handler.ts:29`, `response.ts:30` |
| Conditional `await` so sync handlers pay no microtask | `compile.ts:33` |
| `cork()`+`uncork()` to coalesce header+payload writes | `connection.ts:586` |
| Manual `Content-Length` to avoid `chunked` | `response.ts:74` |

## What is NOT included

- No HTTP server implementation — Node's `http`/`https`/`http2` are used as the transport.
- No logging, no cluster, no static file server (files are streamed with `pipeline`, but there is no middleware doing directory listing).
- No room/channel management for WebSockets — that is app-level.

## Public entry point

The package exposes a **single entry point** (`package.json` `exports`): `@panmdaa/server`, a root barrel (`src/index.ts`) re-exporting every domain.

```ts
import {
  Server, Router, cors, NotFound,
} from "@panmdaa/server";
```

The `error`, `http`, `middleware`, `router` and `ws` barrels are internal and reachable only through the root export.
